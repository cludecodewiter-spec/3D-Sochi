# 交互与 UI 设计书(UX Design Specification)

- 项目:除害装置 3D 维护训练系统(3D-Sochi)
- 文档:docs/design/UX_DESIGN.md
- 作者:设计代理 D2(交互 / UI)
- 方法:先从用户旅程独立设计,再对照现状(差异只写在第 7 章)
- 约束(冻结项,本设计全部遵守):
  1. 清单 JSON 数据契约与 glTF 节点名不变;
  2. 一切前进路径必须经 `ProcedureRunner.CanAdvance`,UI 不得提供任何绕过通道;
  3. 免责横幅常驻:「训练辅助,实际作业以官方程序为准」;
  4. 逻辑在 Core、App 只做 UI 呈现。

---

## 0. 设计原则(总纲)

| # | 原则 | 含义 |
|---|------|------|
| P1 | 安全优先于流畅 | 任何"更顺手"的交互都不得削弱安全确认。宁可多一次点击,不可少一次确认。 |
| P2 | 状态永远可见 | 当前步骤、门禁状态、设备运行状态(PLC)三者任何时刻可一眼读出,不依赖记忆。 |
| P3 | 被禁用≠被隐藏 | 不可用的操作要"看得见但按不动",并解释为什么按不动(禁用原因就地显示)。 |
| P4 | 3D 是舞台不是谜题 | 视口只承担"看与操作对象",全部文字信息在侧面板;不在 3D 里放悬浮文字菜单。 |
| P5 | 双语一等公民 | zh/ja 任何界面元素同权重设计,布局按最长语言(通常是日文)预留宽度。 |
| P6 | 手不离流程 | 训练主循环(读指示 → 勾确认 → 操作部件 → 下一步)可全程只用鼠标左键完成。 |

## 1. 三类用户旅程

### 1.1 角色画像

| 角色 | 背景 | 目标 | 关键诉求 |
|------|------|------|----------|
| A. 新员工(首训) | 入职 ≤3 个月,可能第一次见该设备,母语可能是中文或日文 | 完整走一遍拆装流程,建立"顺序 + 安全"的肌肉记忆 | 不迷路、不怕点错、每一步知道"为什么" |
| B. 复训员工(抽考) | 有 1 年以上现场经验,半年一次复训考核 | 快速证明自己仍然记得顺序与安全要点 | 少废话、直达考核、成绩可留存 |
| C. 班组长(演示) | 现场培训负责人,在晨会/培训室投影讲解 | 用大屏演示某一步的要点,穿插提问 | 大字号、可跳步、可随时"拆开给大家看" |

### 1.2 旅程 A:新员工首训(完整路径)

```
启动应用
 └→ [设备库] 看到设备卡片(名称·缩略图·步骤数·预计时长)
     └→ 点击「除害装置 A 型」卡片
         └→ [训练界面] 加载模型(进度指示)→ 自动定位到步骤 1
             ├→ 读右侧步骤指示(黄色卡片:"拧下四角螺栓…")
             ├→ 观察 3D:目标部件呼吸高亮,可旋转/缩放确认位置
             ├→ 逐项勾选安全确认(LOTO / PPE…),必选项带红色「必须」徽章
             │    · 未勾全 →「下一步」灰显 + 就地提示"还有 2 项必须确认"
             ├→ 勾全 →「下一步」变为可用(蓝色实心)
             ├→ (可选)直接拖拽前面板体验插拔:沿轴拔出/回弹
             └→ 点「下一步」→ CanAdvance 通过 → 部件动画拆下 → 进入步骤 2
         └→ …重复至最后一步 → [完成页] 绿色横幅"全部完成"
             ├→ 显示本次用时、翻看过的步骤
             └→ 引导:「再练一遍」/「试试考核模式」/「返回设备库」
```

旅程 A 的体验要点:
- 首次进入训练界面时显示一次性 3 步引导浮层(① 这里读指示 ② 这里勾确认 ③ 3D 里可以拖):可点「跳过」,勾选「不再显示」后持久化。
- 每步的安全确认项默认全部未勾,**换步即清空**,防止"惯性连点"。
- 允许「上一步」回看(部件动画装回),不计错、不惩罚——首训模式没有失败。

### 1.3 旅程 B:复训抽考(完整路径)

```
启动应用
 └→ [设备库] 点击卡片 → [训练界面]
     └→ 顶栏点「考核模式」→ 弹出确认框("进入考核后不显示步骤答案,确定?")
         └→ [考核-①排序] 打乱后的步骤列表 → 拖拽(或上移/下移按钮)排序 → 提交
             └→ 即时评分:顺序正确率(如 5/6),错位项红色标出正确位置
         └→ [考核-②执行] 按标准顺序逐步执行
             ├→ 只显示步骤指示,3D 联动动画
             ├→ 安全确认仍然强制(安全门在考核中不放松,冻结项 2)
             ├→ 每步计时;勾选非必须项也记录(体现严谨度)
             └→ 「下一步」仍走 CanAdvance
         └→ [考核-③结果] 总分 = 排序分 + 执行分(用时/遗漏)
             ├→ 结果页:分项明细 + 通过/不通过判定(阈值可配)
             └→ 「导出成绩(CSV)」/「重考」/「返回训练」
```

旅程 B 的体验要点:
- 考核入口有确认拦截;考核中途点「退出」需二次确认("成绩将不被记录"),防误触作废。
- 排序阶段提供拖拽 + 按钮双通道(拖拽快、按钮无障碍),两者等价。
- 结果页明确区分"知识错误(排序错)"与"安全遗漏(必选未勾)",后者用红色单列突出——安全遗漏是复训最需要暴露的问题。

### 1.4 旅程 C:班组长演示(完整路径)

```
启动应用(投影仪,1080p/4K 大屏)
 └→ [设备库] 点击目标设备
     └→ [训练界面] 顶栏开启「演示模式」开关
         ├→ 字号整体放大一档(≥1.25×),侧栏加宽
         ├→ 步骤面板出现步骤缩略列表(1…N),可直接点跳任意步
         │    · 跳步仅移动"讲解位置",不发放训练完成记录(与受训前进语义分离,
         │      不触碰 CanAdvance——CanAdvance 只管"受训前进",演示跳步是只读回放)
         ├→ 「整体分解」按钮:全部 remove 部件沿各自 removeOffset 爆炸展开
         ├→ 「复原」按钮:一键装回
         ├→ HMI 面板可现场互动:按急停给大家看报警灯闪烁、压力回落
         └→ 讲到某部件:点部件树 → 3D 高亮 + 其余部件半透明(隔离)
     └→ 演示结束 → 关闭演示模式 → 恢复受训布局
```

旅程 C 的体验要点:
- 演示模式是**只读回放**:可跳步、可分解,但不产生任何"完成"状态,退出后受训进度归零重来——从机制上保证演示便利性不构成安全门旁路(冻结项 2)。
- 语言切换按钮在演示时保持可见:班组长常需要中日文对照讲解,切换即时生效、不打断当前步。

## 3. 安全体验设计

### 3.1 安全门的视觉语言(状态机)

「下一步」按钮 = 安全门的唯一 UI 化身,其 `IsEnabled` 严格绑定
`ProcedureRunner.CanAdvance`(冻结项 2:视觉只做呈现,判定只在 Core)。

| 门禁状态 | 按钮外观 | 辅助信息 |
|----------|----------|----------|
| 锁定(有必选未勾) | 灰底 #B0BEC5、深灰字、左侧 🔒 图标、鼠标悬停显示禁用光标 | 按钮正上方红字:"🔒 尚有 n 项必须确认"(实时计数) |
| 解锁瞬间 | 200ms 由灰渐变为蓝 #1976D2,🔒 变 →,轻微放大 1.05→1.0 回弹 | 红字提示消失,替换为灰色"可以前进" |
| 可前进 | 蓝底白字实心,主按钮字重 Bold | — |
| 已到末步 | 按钮替换为绿色"完成 ✓" | 绿色完成横幅 |

安全确认项自身的视觉:

```
☐ 确认主电源已隔离、上锁并挂牌            [必须]   ← 未勾:默认
☑ 确认主电源已隔离、上锁并挂牌            [必须✓]  ← 已勾:行背景淡绿 #E8F5E9
☐ 确认防护装备完好                        (推荐)   ← 非必选:灰色小徽章
```

- 「必须」徽章:红底 #D32F2F 白字;勾选后变绿底 #2E7D32 加 ✓——用"红→绿"给完成感。
- 徽章除颜色外必须有文字("必须/必須"),不做纯色点(色盲可读,见第 6 章)。
- 确认项按 required 优先排序,必选在上。

### 3.2 防误触原则

| # | 原则 | 落地 |
|---|------|------|
| G1 | 确认不可批量 | 不提供"全选"按钮;每个复选框独立点击,点击热区整行(高≥40px)但一次只勾一项。 |
| G2 | 换步即清零 | 前进/后退/重来后所有勾选复位(Core 已如此),UI 加 150ms 逐项淡出动画提示"确认已重置"。 |
| G3 | 破坏性操作二次确认 | 「重来」「退出考核」「返回设备库(训练中)」均弹确认框;确认框默认焦点在"取消"侧。 |
| G4 | 禁用态可解释 | 一切灰按钮 hover 出 tooltip 说明原因("急停按下中,无法启动")。 |
| G5 | 危险按钮隔离 | HMI 急停与启动物理间隔 ≥16px,且急停独占一列(见第 4 章),避免相邻误按。 |
| G6 | 拖拽不越权 | 尚未到达对应 remove 步骤的部件:拖动时只允许 ≤15% 行程的"晃动"随即回弹,并出提示"请先完成当前步骤的安全确认"——直接操作与流程门禁一致,不给"用手绕过安全门"留口子。 |
| G7 | 无静默失败 | 模型/清单加载失败、glTF 节点缺失,均以红色错误卡片展示明细,绝不显示半成品场景。 |

## 4. HMI 触摸屏规范

模拟现场触摸屏,深色面板风格(#10151C 底、#2C3947 描边、内阴影)。目标:在 3D 训练软件内提供"和现场一样"的操作直觉。

### 4.1 布局

```
┌─ HMI タッチパネル ──────────────────┐
│  [ 启动 ]  [ 停止 ]  [ 复位 ]  │((急停))│  ← 急停独立分区,右侧竖向留白隔离
│  进气阀 [ 开 / 关 ]   ●运转  ●报警    │
│  压力 ▂▂▂▂▂▂░░░░ 250 kPa  (量程 0–300) │
│  流量 ▂▂▂░░░░░░░  12.3 L/min (0–50)   │
└──────────────────────────────────────┘
```

### 4.2 按钮规范

| 项 | 规范 |
|----|------|
| 最小尺寸 | 普通按钮 ≥ 88×36px(桌面鼠标);若目标触屏一体机则 ≥ 48×48px。文字 ≥13px Bold。 |
| 启动 | 绿底 #1D8A44,白字。禁用条件(急停中/阀未开/报警中)下灰显 + G4 tooltip。 |
| 停止 | 红底 #C62828,白字。**永远可用**(停止是安全方向,不设禁用)。 |
| 复位 | 中性蓝灰 #3D5570。急停按下时禁用(与 PlcSimulator 逻辑一致)。 |
| 急停 | **圆形蘑菇头**:直径 ≥56px,红底 #C62828 + 黄圈描边 4px #FFD54F(现场 IEC 60204 视觉惯例)。按下后保持"压入"态(深红 #7B1414 + 内阴影),再次点击 = 旋转释放,释放时 200ms 弹起动画。 |
| 进气阀 | 开关式 ToggleButton,ON 态青色描边 + "开/開" 字样;联动 3D 手轮旋转动画(开/关各转两圈)。 |

颜色语义总表(全应用统一):

| 颜色 | 语义 | 使用处 |
|------|------|--------|
| 绿 #1D8A44 / #31E06C | 启动 / 运转中 / 通过 | 启动钮、运转灯、完成态 |
| 红 #C62828 / #FF4438 | 停止 / 报警 / 必须 | 停止钮、报警灯、必须徽章、免责横幅 |
| 黄 #FFD54F | 警示强调 | 急停黄圈、指示卡片边框 |
| 蓝 #1976D2 | 主操作(前进/提交) | 下一步、提交排序 |
| 灰 #B0BEC5 | 禁用 | 一切禁用态 |

### 4.3 灯态规范

| 灯 | 熄灭 | 点亮 | 闪烁 |
|----|------|------|------|
| 运转(绿) | #233041 暗坑 | #31E06C 常亮 + 外发光 | — |
| 报警(红) | #233041 | — | 3Hz 闪烁(与 3D 信号灯塔同步相位) |

- 灯旁必须有文字标签(运转/運転、报警/警報),灯 ≥12px 直径。
- HMI 灯态与 3D 内 LED / 信号灯塔由同一 `PlcSimulator` 状态驱动(Core 单一数据源),UI 两处只读渲染,保证永不打架。

### 4.4 量程条(压力/流量)

- 水平条,高 8px,背景 #1A222D;填充蓝 #1976D2;数值右对齐等宽字体,单位恒显(kPa / L/min)。
- 超过量程 85% 时填充色渐变为橙 #F57C00(预警),100% 封顶不溢出。
- 条形 + 数字双编码;数值变化用 250ms 缓动,与 PlcSimulator 一阶惯性一致,呈现"真实表计"的迟滞感。

## 5. 拖拽插拔交互规范

### 5.1 基本模型

- 每个可拆部件的插拔轴 = 其 remove 步骤的 `removeOffset` 归一化方向;行程 = `|removeOffset|`。无 removeOffset 的部件(highlight 类)不可拖拽,只可点选。
- 拖拽自由度 = **1 维(沿轴滑动)**:把鼠标射线投影到轴线求最近点参数 t,clamp 到 [0, 1.3×行程](允许 30% 过冲,松手回位),部件严格沿轴运动,不允许自由 3D 平移——既符合导轨/插槽的物理直觉,也彻底避免"部件被拖丢"。

### 5.2 吸附与回弹

| 松手时拔出量 t | 行为 |
|----------------|------|
| t > 60% 行程 | 吸附到"完全拔出"位(200ms 缓出) |
| t ≤ 60% 行程 | 回弹到"完全装入"位(带 5% 过冲的弹性曲线,给"咔哒"装配感) |
| 装回时 t < 10% | 触发轻微震动式抖动 1 帧 + 高亮闪一下 = "到位反馈" |

- 阈值 60% 为默认,内容侧可按部件在清单外配置覆盖(不动 JSON 冻结契约,用旁路配置文件)。
- 与流程联动:仅当"当前步骤 action=remove 且 targetPart=该部件 且 CanAdvance 为真"时才允许拔到位;拔到位等价于按下「下一步」前的预演——真正的步进仍必须点「下一步」经 CanAdvance(冻结项 2)。未解锁部件按 G6 只给 ≤15% 晃动。

### 5.3 与视角旋转的手势冲突消解

| 规则 | 内容 |
|------|------|
| R1 命中即夺权 | pointerdown 时做射线命中:命中可拖部件 → 立即 `controls.enabled=false` 并 setPointerCapture,本次手势归拖拽;未命中 → 归轨道旋转。二者互斥,绝不中途切换。 |
| R2 点击与拖拽区分 | 位移 < 4px 且 <300ms 松手 = 点选(高亮部件),不产生任何位移;超过即为拖拽。 |
| R3 拖拽中的视觉 | 光标变 grabbing;沿轴显示半透明导轨线(起点→终点 + 终点处虚影轮廓),提示"能拔到哪"。 |
| R4 手势结束恢复 | pointerup/pointercancel 一律恢复 controls,释放捕获;窗口失焦视为 pointercancel(防卡死在拖拽态)。 |
| R5 触屏双指保留 | 双指手势(缩放/平移)永远归相机,即使起点落在部件上——单指才可能是拖拽。 |
| R6 桌面等价键 | HelixToolkit 侧:左键 = 命中拖拽/点选,右键 = 旋转,中键 = 平移,滚轮 = 缩放;拖拽期间吞掉左键的相机绑定。 |

### 5.4 反馈层次

1. hover 可拖部件:轮廓微亮 + 光标 grab;
2. 拖拽中:部件亮度 +20%,导轨线可见;
3. 非法拖拽(未到步骤):晃动回弹 + 面板侧安全提示条闪烁一次(把用户视线引回安全确认区)。

## 6. 中日双语与无障碍

### 6.1 双语

| 规则 | 内容 |
|------|------|
| L1 | 全部 UI 静态文案走资源文件(zh/ja 两套),清单内容文案走 `LocalizedText` 按当前语言取值、缺失回退另一语言并加"(ZH)/(JA)"标注,不显示空串。 |
| L2 | 语言切换即时生效(含 HMI、部件树、步骤、考核、tooltip、错误信息),不重启、不打断当前步骤与勾选状态。 |
| L3 | 默认语言 = 日语(现场部署地),可记忆用户上次选择。 |
| L4 | 布局按日文最长串设计宽度(日文平均比中文长 20–40%);按钮文字禁止截断,超长自动缩字号一档而非省略号。 |
| L5 | 字体:中文 Noto Sans SC / 日文 Noto Sans JP(或系统 Yu Gothic UI),数字单位用等宽字体。 |

### 6.2 无障碍

| 项 | 规范 |
|----|------|
| 字号 | 正文 ≥14px,步骤指示 ≥15px,HMI 标签 ≥12px;演示模式整体 ×1.25。提供"大字"开关(×1.25/×1.5)。 |
| 对比度 | 正文对比度 ≥4.5:1,大字/图标 ≥3:1(WCAG AA)。深色 HMI 面板上的次要文字由低对比灰提到 #B8C7D9 以过线。 |
| 色盲友好 | 所有"红/绿"语义都加第二编码:运转灯=绿+常亮+「运转」字,报警灯=红+闪烁+「报警」字;必须徽章=颜色+文字;门禁=颜色+🔒图标+计数文案。不出现仅凭红绿区分的元素。 |
| 键盘 | Tab 顺序:安全确认 → 上一步 → 下一步;Space 勾选;Enter 触发默认按钮;考核排序支持 Ctrl+↑/↓。 |
| 焦点可见 | 2px 高亮描边焦点环,深浅底色各一套颜色。 |
| 动画 | 所有动画 ≤400ms,提供"减少动画"开关(部件位移瞬时完成)。 |
