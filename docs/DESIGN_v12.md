## §1 一页纸

**一句话**：你是一个靠手艺吃饭的偷车贼，而手艺正在过时。

**类型**：文本驱动的犯罪经营 + 叙事模拟
**平台**：浏览器（TypeScript / 无引擎）
**时长**：约 46 小时主线，三纪
**视角**：第二人称，全中文

### 三根支柱

**一｜手艺是有质感的**
偷一辆车不是点一次按钮。它是四个阶段、四次判断，每次判断前你只能看到**不完整的征兆**。
成功时你知道自己为什么成功。这是本作一切爽感的来源。

**二｜你永远不知道谁在说真话**
情报是这个游戏的货币。而情报会错——有时因为对方在骗你，有时因为对方自己也不知道。
**这两种错必须让玩家能够区分，因为应对方式完全不同。** 这是本作的灵魂。

**三｜时代不会让你失败，它只是让能容下你的地方越来越小**
Marco 的技能永远有效。只是能用上它的车，一年比一年少。
这个主题不通过剧情说出来，通过**可下手车辆池的逐年萎缩**让玩家自己算出来。

### 三纪

| | 标题 | 时长 | 内核 | 你的处境 |
|---|---|---|---|---|
| 第一纪 | **手艺** | ~12h | 一根铁丝 | 你一个人，欠着钱 |
| 第二纪 | **网络** | ~16h | 你不再亲自动手 | 你有了队伍、情报网、保护伞 |
| 第三纪 | **过时** | ~18h | 你的手艺打不开这把锁 | 你有一切，除了时间 |

## §3 核心循环

```
回合开始（1 天 = 3 行动点）
   │
   ├─ 收情报 ──→ 线人 / 踩点 / 暗网       （1 AP）
   │
   ├─ 验证 ────→ 交叉比对，得到二次信号     （1 AP + $）
   │
   ├─ 执行 ────→ SegmentRun（偷车/运输/追车/比赛）（2 AP）
   │
   ├─ 变现 ────→ 选择销赃渠道               （1 AP）
   │
   └─ 回合结束 ──→ 热度衰减 / 债务计息 / 生成今日摘要卡
```

**每一步都会写进事件日志。** 事件日志是档案库、存档、结局剪报集的**唯一数据源**（见 §9）。

## §4 SegmentRun：统一的执行引擎 ⟨S1⟩

v11 为比赛、运输、追车分别设计了三套系统，另有偷车的四阶段。**这四者结构完全相同**，v12 合并为一套引擎。

### 4.1 结构

```
一次 SegmentRun = N 个段落，按顺序推进

每段：
  1. 呈现【征兆】—— 不完整、可能被错误情报污染的信息
  2. 玩家从 3 个选项中选一个（另有随时可选的【放弃】）
  3. 判定 → 结算
  4. 更新【持续状态量】
  5. 状态量影响后续段的难度、可选项与征兆质量

**最后一段的判定结果，就是整次行动的结果。** 中途失败只会让后面更难；
脱离阶段砸了不会让你带着一辆刮花的车回家，那就是这次行动输掉的方式。
```

### 4.2 配置一览

| 配置 | 段落 | 持续状态量 | 主用技能 |
|---|---|---|---|
| **偷车** | 踩点 → 接近 → 破解 → 脱离 | 动静 / 耗时 / 车况 | 潜行·机械·电子·驾驶 |
| **翻车** ⟨新增⟩ | 开门 → 翻找 | 动静 / 耗时 | 开锁·隐匿·电气 |
| **扒窃 / 撬取款机 / 入室 / 持械抢劫** | 各 2-3 段 | 动静 / 耗时 / 到手 | 隐匿·开锁·演技 |
| **洗劫赌厅** ⟨新增⟩ | 混进去 → 出纳台 → 带着钱出去 | 同上（到手可为负） | 演技·开锁·电气 |
| **挑帮派的账房** ⟨新增⟩ | 门口那两个人 → 房间里 → 走人 | 动静 / 耗时 / 到手 | 隐匿·开锁·驾驶 |
| **追车** | 甩开 → 路线 → 对峙 → 消失 | 车况 / 油量 / 意志 | 驾驶·胆识 |
| **运输** | 出城 → 检查站 → 夜宿 → 入城 | 疲劳 / 注意度 / 货损 | 驾驶·胆识 |
| **比赛** | 起步 → 中段 → 关键弯 → 冲刺 | 车况 / 轮胎 / 领先度 | 驾驶 |

**翻车**是这套结构最划算的一次复用：同一辆 2016 年的车，
它的电子防盗能把「开走它」这条路彻底堵死，却堵不住它的车窗。
偷车失效的时代里，这是玩家还做得动的手艺——而它一行引擎代码都没多写。

**一套代码，多份配置。** 好处不只是省工时——玩家学会一次，四种玩法全都会玩，这本身就削掉了一大截上手门槛 ⟨S2⟩。

### 4.3 征兆（Tells）

征兆是本作最重要的呈现设计。规则：

1. **征兆永远是观察，不是数字。**
   ✅「他的车尾在抖——轮胎快到极限了。」
   ❌「对手轮胎耐久 23%」

2. **征兆的准确度取决于你的情报质量。**
   - 有**真情报**覆盖该段 → 征兆准确
   - 无情报 → 征兆模糊（"看不清里面有几个人"）
   - 有**假情报** → **征兆自信地说谎**

第 3 条是全案最关键的一行规则。它让错误情报的代价不是「少一点成功率」，而是**你以为自己知道，其实不知道**。玩家会基于假征兆做出一个在他看来完全合理的选择，然后 Marco 中枪。

3. **胆识（nerve）技能提高读征兆的分辨率。** 高胆识会额外看到一行：「……但这话他说得太顺了。」

### 4.4 放弃

每段都能【放弃】。放弃的代价随进度递增：

| 放弃于 | 代价 |
|---|---|
| 第 1 段 | 无，只损失 AP |
| 第 2 段 | 动静已经造出来了，热度 +5 |
| 第 3 段 | 热度 +12，可能被目击 |
| 第 4 段 | 车丢了，热度 +20，但人跑掉了 |

**「及时收手」必须始终是一个正确的选择。** 这是本作难度曲线的安全阀。

## §5 数值模型 ⟨S6-b⟩

> v11 通篇没有一个公式。以下是全部。所有数值域为 `0–100` 除非另有说明。

### 5.1 技能

| 键 | 名称 | 用途 |
|---|---|---|
| `stealth` | 潜行 | 踩点、接近、不被目击 |
| `mechanical` | 机械 | 撬锁、热线（**对 2005 年前的车永远有效**） |
| `electronic` | 电子 | 现代车的点火与防盗（Marco 初始为 5） |
| `driving` | 驾驶 | 脱离、追车、运输、比赛 |
| `nerve` | 胆识 | 读征兆的分辨率、高压下的判定 |

**Marco 初始**：潜行 55 / 机械 78 / 电子 5 / 驾驶 45 / 胆识 60
（机械 78 是他的骄傲。电子 5 是第三纪的整个悲剧。）

### 5.2 车辆防御

每辆车四个防御维度，对应偷车的四段：

```
exposure   曝光度   → 踩点与接近的难度（停放位置、人流、监控）
lock       锁具     → 破解阶段·机械路径
ignition   点火系统 → 破解阶段·电子路径
pursuit    追缉度   → 脱离阶段（车的显眼程度、被追的可能）
```

**年代决定形态**（这是主题的数值载体 ⟨S7⟩）：

| 年代 | lock | ignition | 说明 |
|---|---|---|---|
| `classic` ≤1995 | 20–40 | **10–25** | 铁丝有效。Marco 的黄金时代 |
| `modern` 1996–2010 | 40–60 | 45–65 | 两条路都能走 |
| `contemporary` ≥2011 | 55–75 | **85–98** | 机械路径**直接不可用** |

破解阶段玩家可选机械路径或电子路径，两条路径面对的对抗值不同：

```
电子路径对抗值 = ignition
机械路径对抗值 = lock + max(0, ignition - 40) × 3
```

第二个公式是对物理现实的直译：**防盗锁止系统（immobiliser）不是一把更难撬的锁，它让热线这件事在原理上失效。** 撬开车门只是第一步，车打不着火。代入三个年代：

| 年代 | 机械路径对抗值 | Marco（机械 78）的成功率 |
|---|---|---|
| `classic` | 30 + 0 = **30** | 0.74 |
| `modern` | 50 + 45 = **95** | 0.42 |
| `contemporary` | 65 + 156 = **221** | **0.05（触底）** |

系数取 3 而非 2，是为了让**触底不可被选项修正救回来**：破解阶段最激进的选项（撬方向盘柱）自带 +0.15，若系数为 2，现代车上它会把成功率抬到 0.20——那样第三纪那场戏就不成立了。

对 `contemporary` 的车，机械路径的选项**依然显示、依然可点**，判定结果是 0.05 的下限。
这正是第三纪那场戏的机制来源：*锁芯里什么都没有。这不是一把锁，这是一台电脑。*

保留 5% 而不是设为 0，是有意的：**它意味着 Marco 并非在原理上不可能成功**，所以「再试一次」在他自己看来是合理的。这比一个写死的「必定失败」心碎得多。

### 5.3 判定公式

```
p = 0.50
  + (skill - defense) / 200        // 技能差，范围 ±0.50
  + optionModifier                 // 选项自带，-0.20 ~ +0.20
  + intelModifier                  // 情报：真 +0.15 / 无 0 / 假 -0.10
  - heat / 500                     // 热度惩罚，最多 -0.20
  - stateVarPenalty                // 持续状态量（动静高、车况差…）

p = clamp(p, 0.05, 0.95)
```

**上下限 0.05 / 0.95 是硬规则**：永远有意外，也永远有希望。
**教学关不例外。** 第一次偷车时 Solomon 站在旁边，这在数值上是一个 **+0.20 的公开修正**（界面上写明「所罗门就站在你旁边，低声说着每一步」），把四个阶段全部顶到 0.95 上限——但四段连乘之后仍然约有五分之一的可能失败。
这是有意的：**「及时收手」和「第一次就搞砸」必须都是真实可能的结果**，否则第 §4.4 节的安全阀就是假的。第一小时的承诺是「你会偷到一辆车」，那是对这一个小时说的，不是对第一次尝试说的。

**难度修正**（§8）：故事 `p' = p + (1-p)*0.25`；标准 `p' = p`；硬核 `p' = p - 0.05`。

### 5.4 热度

```
热度 0–100，每回合结束结算

累加：
  成功偷车        + vehicle.pursuit / 10        (约 +3 ~ +9)
  失败但逃脱      + 8
  被目击          + 12
  使用暴力        + 25
  放弃于第 3/4 段 + 12 / 20

衰减：
  该回合有犯罪行为   - 3
  该回合无犯罪行为   - 5
  贿赂（第二纪解锁） - 15（一次性，$）
```

| 热度 | 状态 | 效果 |
|---|---|---|
| 0–19 | 平静 | — |
| 20–39 | 留意 | 销赃价 -8% |
| 40–59 | 关注 | 判定 -0.08；随机巡逻遭遇 |
| 60–79 | **专案** | 判定 -0.12；**档案库出现「你自己的案卷」** |
| 80–99 | 通缉 | 判定 -0.16；每回合被捕检定 |
| 100 | — | 触发失败状态【被捕】 |

> 这张表里的判定惩罚**不是独立数值**，它就是 §5.3 那个 `-heat/500` 线性项在各档边界上的取值
> （40→-0.08、60→-0.12、80→-0.16，恰好吻合）；销赃惩罚同理来自 §5.5 的 `1 - heat/250`。
> 表只负责给区间起名字。**代码里不得再存一份这些数字**——早期版本存过，
> 结果那份表从来没有被任何地方读取，谁去调它都不会有任何效果。

热度 ≥60 时档案库里出现你自己的警方案卷，随热度增长逐条填充 —— 这是**用文档形态呈现压力** ⟨S3⟩，比任何进度条都有效。

### 5.5 经济

```
销赃价 = basePrice
       × channelRate            // 渠道
       × (condition / 100)      // 车况，来自脱离阶段
       × (1 - heat / 250)       // 热度，最多 -40%
       × (1 - demandDecay)      // 市场饱和
```

| 渠道 | 费率 | 解锁 | 特性 |
|---|---|---|---|
| 街头拆车场 | 0.35 | 第 1 回合 | 即时，无风险 |
| 熟人销赃 | 0.50 | 第 4 回合 | 需要关系 ≥ 20 |
| 出口订单 | 0.70 | 第 14 回合 | **延迟 3 回合到账**，期间可能被截 |
| 加密洗白 | 0.60 | 第三纪 | **热度 -10**，但留下可追溯的链 ⟨S1-b⟩ |

`demandDecay`：同型号车每次销赃后该型号 +8%（上限 40%），每 5 回合恢复 8%。
→ 逼玩家换目标，天然产生内容轮换。

#### 5.5' 赃物：产出是**东西**，不是一个数字 ⟨新增⟩

原先一次入室的结算是 `take += 1800`。这既没有质感，也让「只拿一件就走」
这种最像小偷的玩法完全无法表达。现在拆成两半：

```
散钱   → 直接进现金（数额相应下调）
东西   → 抽自赃物表，进赃物袋，要另外出手
```

四张表，按你在什么地方翻：

| 表 | 场合 | 典型内容 |
|---|---|---|
| `vehicle` | 车里 | 收音机 · 吸盘导航 · 落在座位上的手机 · 手套箱里的证件 |
| `house` | 屋里 | 名牌包 · 首饰盒 · 衣柜夹层里的信封 · **床头柜里的左轮** |
| `counter` | 柜台后 | 收银机里的现钞 · 几条烟 · 一沓刮刮乐 |
| `pocket` | 身上 | 钱包 · 零钱 · 墨镜 |
| `casino` | 赌厅后厅 | 高额筹码 · 出纳台的现钞 · 小金条 · **抽屉里的手枪** |
| `den` | 帮派账房 | 帆布袋里的现钞 · 收数本 · **靠墙的霰弹枪** |

**枪只出现在后三张里的三张：`house` / `casino` / `den`。**
共同点是你必须走进去。街上和别人口袋里永远摸不到枪——
「灭口」和「开枪」这两个选项，是玩家自己一步一步走过去拿到的。

出手：**现金按面值，其余六五折**。两样东西卖不掉——
手套箱里那叠证件（没人会买，但上面有名字和地址），
以及那把左轮（它的价值不在钱上，见 §7.0）。

`take` 与 `draws` 的分工是一条硬规则：**凡是能被描述成一件东西的，
就不要写成数字。** 玩家记得住「衣柜夹层里的那个信封」，记不住 +1800。

### 5.6 债务（第一小时的钩子）

```
初始债务    $12,000
周期        每 7 回合结算一次
利息        未偿本金 × 12%
最低还款    $1,500
```

| 未达最低还款次数 | 债主的反应 |
|---|---|
| 1 | 电话。语气还算客气 |
| 2 | 他们打断了 Diana 的手。她 5 回合内无法行动 |
| 3 | 最后通牒：一个回合 |
| 4 | 失败状态【被清算】 |

**首次电话在第 2 回合**，告知第 7 回合要交 $1,500。
→ 玩家必须在 5 个回合内完成「踩点 → 偷 → 卖」的完整闭环。这就是第一小时的全部驱动力。

### 5.7 行动点

每回合 3 AP。

| 行动 | AP |
|---|---|
| 见线人 / 踩点 / 逛暗网 | 1 |
| 验证一条情报 | 1（另需 $） |
| 执行 SegmentRun | 2 |
| 销赃 | 1 |
| 休息 | 全部（恢复队友状态，热度 -5） |

3 AP 意味着「踩点 + 偷 + 卖」正好用满一天。玩家想同时做别的，就必须放弃其中一环 —— **AP 是本作最主要的取舍压力来源**。

## §6 情报系统（本作的灵魂）

### 6.1 两种不同的错

v11 只有一个「可靠度」维度。v12 拆成两个**隐藏**属性：

```
honesty  诚实度  他会不会骗你
access   渠道    他知不知道
```

这产生四种线人，而**应对方式完全不同**：

| | access 高 | access 低 |
|---|---|---|
| **honesty 高** | 金矿。保护他 | 好人，但没用。别为他的情报付钱 |
| **honesty 低** | 最危险。他知道真相，却选择卖你假的 | 吹牛的。便宜，当噪声处理 |

玩家永远看不到这两个数字。他只能从**历史模式**里推断：
- 「他的情报错的时候，总是错在**关键细节**上」→ 这是恶意
- 「他的情报错的时候，方向是对的，数字不准」→ 这是无知

**档案库的存在，正是为了让玩家能做出这个推断**（见 §9.2）。

### 6.2 情报的真值

```ts
type Truth = 'true' | 'partial' | 'false'
```

生成时：`p(true) = honesty/100 × 0.5 + access/100 × 0.5`，加 ±0.1 噪声。
`partial` = 方向正确、关键数字错误（"两个看守" → 实际四个）。**partial 是最好的内容**，因为它让玩家学会不信任精确数字。

### 6.3 应用到 SegmentRun

| 情报真值 | 判定修正 | 征兆表现 |
|---|---|---|
| `true` | +0.15 | 准确 |
| 无 | 0 | 模糊（"看不清里面有几个人"） |
| `partial` | +0.05 | **方向对，数字错** |
| `false` | **-0.10** | **自信地说谎** |

### 6.4 验证

花 1 AP + $200，找另一个线人交叉比对，得到一个二次信号。
**二次信号本身也可能错**（取决于验证者的 honesty/access）。

→ 验证不给你真相，只给你**第二个数据点**。这是对的：这个游戏里没有任何机制能给你确定性。

### 6.5 后果回写：只写玩家看得见的东西

情报导致的每一个结果**自动写回事件日志并关联到来源线人**。
但写回的**不是这条情报的真值**，而是**玩家实际观察到了什么**：

| 情形 | 档案库显示 |
|---|---|
| 埋伏兑现 | **错的** —— 六个人在等你，这无可辩驳 |
| 行动栽在这条情报覆盖的那一步，且现实确实与它相悖 | **错的** |
| 行动栽在那一步，但它其实是真的 | **说不好** —— 运气差不该算在线人头上 |
| 走到了那一步，行动成功 | **准的** |
| 根本没走到那一步 | **说不好** |
| 中途放弃 | 仍然「没用过」，留在手上 |

两条推论，都是有意的：

- **一条假情报如果蒙混过关，骗子会因此挣到信任。** 玩家没看见任何东西，
  游戏就不能替他看见。
- **一条真情报不会因为一次背运而被记成错。** 否则就是在玩家最需要的那个信号里注入噪声——
  §6.1 要求玩家能从错误的**形状**分辨恶意与无知，那个形状必须干净。

> **实现约束**：`IntelItem.truth` 是隐藏字段，`src/ui/` 下**任何代码都不得读取它**。
> 档案库与可靠度统计只读 `IntelItem.outcome`。这条由测试守着。



```
第 89 回合 · BENNY WALSH
  情报：「7 号仓库周四有货，两个看守」
  你的行动：执行偷车
  结果：❌ 实际有六个。Marco 肩部中枪，休养 4 回合。
  关系：-15
```

这条关联**不是手工写的内容**，是从事件日志自动推导出来的（§9.2）。这正是 v11 说的「玩家不需要自己记，游戏帮他记」能够成立的技术前提。

## §7 被发现，与失败状态 ⟨S6-a⟩

### 7.0 被发现是一个**环节**，不是一个结果 ⟨新增⟩

> 这一层此前整个是缺的。原先的判定链是「掷一次骰子 → 成或败 → 你走掉了」，
> 于是失手永远只有一种后果：什么都没拿到，回家。
> 这既不像现实，也把整个玩法的紧张感砍掉了一半。

**犯罪不会自己「被发现」。它要么被一个人看见，要么被一台机器录下来。**
搞砸一步之后先掷发现判定（`systems/incident.ts` · `DISCOVERY`）：

```
动静炸了 / 触发硬失败规则  → 警察直接到场（必然）
否则                       p = 0.18 + 动静×0.005 + (这一趟已经黄了 ? 0.32 : 0)
                             上限 0.92
被发现时                    65% 是人，35% 是保安公司的探头
```

**三种发现者，三套完全不同的出路。** 出路对应人物特长（§5.1）：

| 发现者 | 出路 | 判定 | 代价 |
|---|---|---|---|
| **人** | 把话圆过去 | 演技 42 | 成了什么都不留 |
| | 塞钱 | 演技 30 · $400 | 有人收了钱还是会打电话 |
| | 吓住他 | 演技 50 | 他会记得这张脸 |
| | **灭口** | 射击 45 · **需要枪** | **底案 +22，永不衰减** |
| | 转身就跑 | 隐匿 36 | 这一趟到此为止 |
| **监控** | 砸掉它 | 开锁 30 | 动静 |
| | 拔硬盘 | 电气 55 | 干净，但 Marco 电气只有 5 |
| | 不管它 | 不用赌 | **底案 +8**，录像会归档 |
| **警察** | **开枪** | 射击 62 · **需要枪** | 成：**底案 +32**；败：重伤 + 被捕 |
| | 跑 | 驾驶 56 | 败即被捕 |
| | 把手举起来 | 不用赌 | 直接进局子 |

两条关键规则：

1. **手上没枪的时候，「灭口」和「开枪」根本不出现在界面上。**
   那把左轮只在住宅的赃物表里（`LOOT_TABLES.house`）。也就是说，
   玩家要先入室，才可能拿到那个把整局游戏变味的选项。
   这条路是玩家自己走过去的，不是系统发的。
2. **处理干净了，这一趟还能接着干。** 这是「不是一次失败就回去了」的落点：
   发现环节挡在下一段前面，不是挡在门口。

### 7.1'  进局子：三次是无期 ⟨新增⟩

被捕不是叙事修辞，是一条会计规则：

```
前科 +1
身上的赃物全部登记收走
这一趟作废（但已经落到你身上的东西先入袋，再被没收——人赃并获就是这个顺序）
刑期  第 1 次 8 天 / 第 2 次 18 天 / 第 3 次没有刑期
```

在里面的每一天：行动点为 0，通缉度照凉，**债期照到、利息照滚**。
这是这套系统最诚实的一句话——牢里唯一在变好的东西是警方的记忆。

**第三次被捕 = 终局。** 与 §7.4 并列，是本作第二个真正的 game over。

---

> 以下四种失败，**其中三种不是游戏结束，而是转入收束线**。

### 7.1 破产
**条件**：现金 < 0 且无可变现资产，持续 3 回合
**不是结束** → 收束线【**借新还旧**】
你被迫接下一个你不想接的活。委托人指定目标、指定时间、指定手法。
你失去选择权，但你还活着。**本作最好的一段被动叙事发生在这里。**

### 7.2 被捕
**条件**：热度 100，或在「警察到了」环节走到被捕（见 §7.0）
**不是结束** → 收束线【**里面**】
审讯。一个纯对话场景，唯一的问题是：**你说出谁的名字？**
- 谁都不说 → 刑期加长（跳过 8 回合），但所有关系 +20
- 说出一个人 → 刑期减半，那个人**永久离开**，其余所有人的关系 -25
- 说出 Solomon → 有一条只有这条路能看到的结局分支

### 7.3 队友尽失
**条件**：Diana 与 Solomon 都不可用（离开 / 死亡 / 入狱）
**不是结束** → 收束线【**一个人**】
所有需要队友的玩法关闭。游戏回到第一纪的形态：只有你和一根铁丝。
**难度不上升，反而下降** —— 但内容量骤减。这是本作最残酷的惩罚方式：不是让你打不过，是让你**没事可做**。

### 7.4 被清算
**条件**：债务违约达 4 次
**这是唯一真正的结束。** 无收束线，直接进结局演出（剪报集，标题是别人的名字）。

## §8 上手门槛：解锁曲线与三档难度 ⟨S2 / S4⟩

### 8.1 系统解锁表

**三条硬约束**：
1. 未解锁的系统在 UI 上**完全不存在**（不是灰掉——灰掉的按钮也是认知负荷）
2. 任意两次解锁之间**至少间隔 3 个回合**
3. 每次解锁**必定**伴随一个 Solomon 顾问场景

| 回合 | 解锁 | Solomon 说 |
|---|---|---|
| 1 | 车辆查看 · 四阶段偷车 · 街头销赃 | 「先看三样东西：它停在哪、锁是什么年代的、跑起来有多显眼。」 |
| 2 | 债主电话 | *（剧情，非解锁）* |
| 3 | 线人与情报 | 「没人会白给你消息。在你信他之前，先问自己——他为什么要告诉我？」 |
| **6** | **档案库** | 「我这辈子记不住的事，都写下来了。你也该有个本子。」 |
| 9 | 热度 | 「条子不是突然出现的。他们是慢慢攒够了理由。」 |
| 12 | 情报验证 | 「一个人说的话是话。两个人说的一样，那才叫消息。」 |
| 15 | 队友（Diana） | 「你老了。有些事该让能跑的人去跑。」 |
| 18 | 销赃渠道扩展 | |
| 21 | 腐败网络 | 「别把这当成买东西。这是养一条狗。你得一直喂，而且它随时可能咬你。」 |
| 24 | 地盘 | |
| 第三纪 | 暗网 · 加密通道 | *（由 Kai 教学，不是 Solomon —— 这个交接本身就是叙事）* |

**档案库排在第 6 回合**，因为那才是玩家第一次真的记不住东西的时候。v11 把它当成新手工具，是误判 ⟨S2⟩。

**热度排在第 9 回合，而不是更早**：让它先在暗处积累几个回合，等玩家打开面板时那个数字已经是 25 了。
「他们是慢慢攒够了理由」这句话，在玩家亲眼看到自己攒了多少之后才有分量——比在 0 的时候教它强得多。

> **实现注记**：三回合间隔由 `systems/unlocks.ts` 在运行时强制，而不是靠这张表自觉。
> 后来往表里加一条，不会意外造成两个教学撞在同一天。第一版的表就违反过这条规则，是单测抓出来的。

### 8.2 三档难度

**任何一档都不替玩家判断情报真假。** 这是不可协商的 ⟨S4⟩。

| | 故事 | 标准 | 硬核 |
|---|---|---|---|
| 情报真假判断 | **玩家** | **玩家** | **玩家** |
| 线人可靠度评分 | 显示 | 显示 | **不显示** |
| 顾问提示 | 常驻 | 关键节点 | 关闭 |
| 判定修正 | `p+(1-p)×0.25` | — | `p-0.05` |
| 失败后果 | 可挽回 | 标准 | 永久 |
| 债务压力 | ×0.5 | ×1.0 | ×1.4 |
| 腐败/地盘维护 | 自动 | 建议 | 手动 |

可随时更改。改动记入事件日志（诚实优先于虚荣）。

## §9 技术规格 ⟨S6-c⟩

### 9.1 事件日志：唯一真相源

**这是整个架构的支点。**

```ts
interface GameEvent {
  id: string
  turn: number
  type: EventType            // 'heist' | 'intel' | 'sale' | 'debt' | 'injury' | ...
  actors: string[]           // 关联实体 id（线人/队友/车辆/地点）
  payload: unknown           // 类型化的具体数据
  causedBy?: string          // 指向另一个事件的 id —— 因果链
}
```

`causedBy` 是关键字段。它让「这条情报导致了什么」成为**一次图遍历**，而不是一份需要手工维护的第二数据源。

一份日志，四种用途：

```
事件日志 ──┬──→ 存档（日志 + seed 即可完整重建状态）
           ├──→ 档案库（按 actor 分组 + 沿 causedBy 展开）
           ├──→「上次怎么了」浮条（该 actor 的最近一条负面结果）
           └──→ 结局剪报集（筛选高影响力事件，渲染为报纸）
```

### 9.2 档案库 = 派生索引，不是存储

```ts
function buildDossier(log: GameEvent[]): DossierIndex
```

纯函数，无状态。任何时候可从日志重建。
→ 不存在「档案库和实际状态不同步」这类 bug，因为它们是同一份数据。

§6.1 说的「从历史模式推断线人是恶意还是无知」，实现上就是对该线人的情报事件按 `truth` 分组统计 —— 免费得到。

### 9.3 可播种 RNG

```ts
class Rng {
  constructor(seed: number)
  next(): number          // [0,1)
  get state(): RngState   // { seed, step }
}
```

**所有随机数必须走这里。** 存档存 `{seed, step}`。
好处：完全可复现 → 可调试、可写确定性单测、日后可做「同一局挑战」。

### 9.4 存档 schema

```ts
interface SaveFile {
  version: number          // schema 版本，用于迁移
  createdAt: string
  rng: RngState
  state: GameState         // 派生状态的快照（用于快速加载）
  log: GameEvent[]         // 真相源
}
```

迁移：`migrations: Record<number, (s:any)=>any>`，逐版本升级。
**存档必须向后兼容** —— 这是一个 46 小时的游戏，玩家的存档可能横跨几个月的更新。

### 9.5 分层

```
engine/     纯逻辑，零 DOM，100% 可单测
systems/    玩法规则，依赖 engine，零 DOM
content/    带类型的数据常量，零逻辑
ui/         唯一接触 DOM 的一层
```

依赖方向单向向下。`content` 不 import `systems`。

## §10 界面架构

### 10.1 单屏密集面板

界面是**一屏之内全部信息可见**的模拟经营式布局，参照《偷车大盗》系列的框架：

```
┌ 标题栏 ────────────────────────────────────────── [档案库] [_][▭][✕] ┐
├────────────┬─────────────────────────────────┬──────────────────────┤
│ 人物档案    │ 状态条：日 / 行动点 / 现金 /       │ 停车库（槽位格）       │
│  肖像       │        负债 / 下次还款             │                      │
│  五项技能条  ├─────────────────────────────────┤ 线人（肖像格）         │
│  热度条     │                                 │                      │
├────────────┤   城  市  地  图                  │ 手上的消息            │
│ 目标 / 人物 │   （主导航：车与人都是图标）        │                      │
│  信息       │                                 │                      │
│  车辆侧影   │   作案时此处换成【作案现场】        │                      │
│  四维防御条  │                                 │                      │
│  操作按钮   ├─────────────────────────────────┤                      │
│            │ 警方通缉指数 ▓▓░░  [休息][结束这一天 ▶▶] │                  │
├────────────┴─────────────────────────────────┴──────────────────────┤
│ 消息（带颜色的逐行日志，永久滚动）                                      │
└─────────────────────────────────────────────────────────────────────┘
```

三条规则：

1. **地图是主导航。** 车和线人都是钉在所在城区上的图标，点图标即选中。没有单独的「目标列表页」——选择这件事本身发生在空间里。
2. **左栏永远是「你」和「你选中的东西」。** 人物档案常驻，下面那块随选中项切换（车辆信息 / 人物信息），**操作按钮也在那里**——看着一样东西的资料，然后对它动手。
3. **消息日志常驻底部。** 每一条事件按发生顺序、带颜色滚过去。它和档案库读的是同一份事件日志（§9.1），只是一个按时间、一个按人物。

**§8.1 的解锁曲线直接体现在这个布局上**：没解锁的系统连面板都不存在。第 1 天屏幕上只有一辆车和一个「结束这一天」。

### 10.2 程序化美术

不依赖任何外部素材，全部为运行时生成的 SVG：

| 资产 | 生成方式 |
|---|---|
| **车辆侧影** | 5 种车身轮廓（旅行车/三厢/皮卡/双门/现代）× 年代修饰。老车有镀铬饰条，现代车只有一个钥匙感应点——**轮廓本身承载年代**。车况低于 85 时画出可见凹损 |
| **人物肖像** | **警方拼图式合成头像**。脸型/发型/眉/鼻/嘴/眼镜/胡须/帽子由角色 id 哈希决定，同一个人永远同一张脸。背景带写生网格与档案编号 |
| **城市地图** | 街道网格 + 河流 + 八个城区节点，图标按城区聚簇排布 |
| **地图徽章** | 车按 5 种车型、线人按 4 种行当，各画各的（见下） |
| **地点图标** | 13 种场所各一枚，用在信息栏标题与地址行 |
| **地点场景图** | 13 种场所各一张插图；车辆的那张会把它自己的侧影画进画面前景 |

### 图标必须说清「是哪一个」，而不只是「是哪一类」

第一版地图上，所有车共用一个通用车形、所有线人共用一个通用人形。
那等于什么都没说——玩家早就从徽章颜色知道这是车还是人，图标没有新增任何信息，
只能靠逐个点开来确认。

现在每辆车按车型画，玩家扫一眼地图就能挑目标。为此**图标被有意夸张**——
图标不是缩比模型，在徽章尺寸下唯一能存活的特征是车顶轮廓，所以：

| 车型 | 徽章上的辨识点 |
|---|---|
| 三厢 | 车顶只占中段，前后各留出长机舱和长尾厢 |
| 旅行车 | 车顶一直延伸到车尾，完全没有尾厢 |
| 皮卡 | 短驾驶舱，然后**塌下去一个敞开的货斗**，尾门立起 |
| 双门 | 车顶提前起峰，然后一路斜到车尾 |
| 现代 | 一整条不断的弧线，车头车尾都压得很低 |

玻璃是**按徽章底色整块挖空**的——车顶线只有被挖出来才看得见。
第一版没挖，五种车在地图上糊成同一个黑块。

> **由测试守着**：任意两个车型徽章、两个行当图标、两个地点图标、两张场景图
> 都不得产生完全相同的图形。复制粘贴留下的重复资产不会报错，只会悄悄让图标失去意义。

选择「拼图肖像」而不是试图画写实人脸，既是对生成器能力的诚实，也**正好是这个游戏的语域**——本作的核心物件就是一份案卷，这些人本来就该长成警察笔下的样子。

### 10.3 文档形态库 ⟨S3⟩

**砍掉** v11 的「背景 × 天候 × 时段 × 前景」图层乘积（约 42 个美术图层 + 合成器，成本被严重低估）。
**投入** 文档形态库 —— 纯 HTML + CSS 模板。

| 形态 | 用途 |
|---|---|
| `newspaper` 报纸剪报 | 你的案子上了新闻；结局剪报集 |
| `surveillance` 监控帧 | 踩点成果；事后被拍到的证据 |
| `calllog` 通话记录 | 债主的电话；线人联系史 |
| `sms` 短信串 | 队友的临场沟通 |
| `ledger` 账本表格 | 收支、分成、债务利息 |
| `map` 手绘地图 | 踩点标注、路线规划 |
| `casefile` 警方案卷 | **热度 ≥60 时出现的、你自己的档案** |
| `note` 手写便条 | 线人塞的纸条、Solomon 的字迹 |

**规则：任何连续 3 个回合内，至少出现 2 种不同形态。** 这是对抗 30 小时疲劳的实际手段——疲劳来自呈现形式单一，不是背景图不够多。

核心手绘插图 **60 张** 保留，用于关键剧情节点与传奇车辆。程序化美术（§10.2）负责其余全部场合。

## §11 「漫长的一周」→ 围剿模板 ⟨S5⟩

不是固定的七天剧本，是一个**按玩家弱点填充**的模板。

**触发**：玩家实力（现金 + 地盘 + 关系网）越过阈值，而非固定回合。

**结构**：7 个回合，每回合一个打击 slot。系统扫描玩家状态，按**当前最薄弱的环节**排序填入：

| 检测到的疏漏 | 填入的打击 |
|---|---|
| 情报只依赖单一线人 | 那个线人被对手买通，开始喂假情报 |
| 腐败网只有单点 | 那个保护伞被带走 |
| 队友长期过劳 | 他倒下，一周内无法行动 |
| 现金流无储备 | 一批货被劫，你付不出下周分成 |
| 从不验证情报 | 手上一半的情报同时被证伪 |
| 地盘扩张过快 | 边缘地盘同时反水 |
| 从不休息 | Solomon 病倒 |

Day 7 固定：**你必须指认是谁在针对你。** 指错的代价比不指认更大。

→ 每周目不同，且**打的是玩家自己留下的口子**。主题重量远超固定剧本：不是「有人在针对你」，是「你自己留下的每一个洞，现在同时被捅了」。

## §12 第三纪：过时 ⟨S7⟩

### 12.1 那场戏（全案情感最高点）

不是两段文字，是**一整个回合的沉默**：

```
你在车库里。手上是一根铁丝。
面前是一辆 2014 年的车。

  [ 尝试撬锁 ]

── 判定：失败 ──

没有任何反应。锁芯里什么都没有。
这不是一把锁，这是一台电脑。

  [ 再试一次 ]

── 判定：失败 ──

你试了四十分钟。
Kai 在办公室里，隔着玻璃看了你一会儿，
然后转过头去继续做自己的事。
他没有笑，他只是不想让你难堪。

  [ 放下铁丝 ]
```

**机制上这不是脚本**：`contemporary` 车辆的 `ignition` 是 85–98，Marco 的 `electronic` 是 5。判定按 §5.3 算出来就是必败。
**这场戏是数值模型的自然结果，不是演出。** 这是本作最值得骄傲的一处设计。

### 12.2 三条路

| | 内容 | 代价 |
|---|---|---|
| **[学]** | 投入回合数学习，`electronic` 可成长至 60 | 期间 `mechanical` 荒废（每 5 回合 -2）；且**每次成功都不带成就感**，因为那不是"你"做到的 |
| **[用]** | 不学，雇 Kai | 省事，但你成了自己讨厌的那种人（老板）。Marco 的技能全部停止成长 |
| **[拒]** | **专攻 2005 年前的老车** | 见下 |

### 12.3 [拒] 不是一次掷骰 ⟨S7⟩

v11 把 [拒] 写成「成功率极低」= 没人会选 = 白做的分支。v12 改为**可行、但世界会萎缩**：

- 铁丝在老车上**依然 100% 有效**，Marco 的机械 78 不打折
- 但老车单车利润只有现代车的 **40–60%**
- 而且**可下手的老车池逐章萎缩**：

| 第三纪章节 | 城内可下手的老车数量 |
|---|---|
| 第 1 章 | 34 |
| 第 2 章 | 27 |
| 第 3 章 | 19 |
| 第 4 章 | 11 |
| 第 5 章 | **4** |

玩家不需要被告知主题。他会自己打开列表，看到那个数字从 34 变成 4。

**时代不会让你失败。它只是让能容下你的地方越来越少。**

## §13 验收标准 ⟨S8⟩

> v11 结尾的「预期评分 9.0」是自我背书。以下换成能测的东西。

**上手**
- [ ] 新手在 60 分钟内完成首次「踩点 → 偷 → 卖」闭环，全程未查外部资料
- [ ] 第 1 天屏幕上只有 2 个可点的东西（那辆车、结束这一天）
- [ ] 第一小时内出现过的**控件种类** ≤ 6（看车 / 踩点 / 下手 / 销赃 / 结束这一天 / 档案库）
- [ ] 任意时刻处于「刚解锁」状态的系统 ≤ 1

> 这条原本写的是「按钮总数 ≤ 12」。实际做出来一数是 52——十辆车各带五个按钮。
> 但把同构的列表项和不同种类的控件混在一起数，本身就是个错的度量：
> 十张一模一样的车卡片不构成认知负荷，六种不同的操作才构成。
> 改成数**种类**，并额外钉死第 1 天的绝对数量。

**信息负荷**
- [ ] 第 5 小时的玩家能正确答出「上一条错误情报是谁给的」
- [ ] 档案库任意条目 ≤ 3 次点击可达
- [ ] 「上次怎么了」浮条在需要它的场合出现率 100%，且零操作成本

**表现力**
- [ ] 单局（10 回合）内出现 ≥ 6 种不同文档形态
- [ ] 任意连续 3 回合内 ≥ 2 种形态
- [ ] 地图上每个图标都能说明它是哪一辆车 / 哪一个行当，无需点开
- [ ] 每种场所都有自己的场景图，且没有两张是同一张

**被发现与后果** ⟨新增⟩
- [ ] 失手之后，玩家看到的是「谁看见了你」，而不是「你走掉了」
- [ ] 手上没枪时，`灭口` 与 `开枪` 在任何界面上都不存在，facade 也拒绝按 id 调用
- [ ] 中途被撞见并处理干净之后，这一趟能继续
- [ ] 灭口 / 打警察 / 放任录像 抬的都是**底案**，贿赂减不掉
- [ ] 第三次被捕直接进结局页，且不再产生刑期
- [ ] 在里面的每一天：行动点为 0，债期照到、利息照滚

**赃物** ⟨新增⟩
- [ ] 一次入室的产出是可以点开的具体物品，不是一个数字
- [ ] 「全部出手」报出的价格与实际到账逐分相等（卖不掉的东西不计入）
- [ ] 那把左轮只能在住宅翻到，且拿到它之后角色才被标为持械
- [ ] 赃物图标全部是真实照片或品类图形，零 emoji

**重玩**
- [ ] 第二周目围剿事件组合与第一周目重合度 < 50%
- [ ] 第三纪三条路各自的专属内容 ≥ 40 分钟

**工程**
- [ ] 同一 seed 的两次运行结果完全一致
- [ ] 存档往返（save → load）后状态与日志逐字节相等
- [ ] `engine/` 与 `systems/` 零 DOM 引用
- [ ] `src/ui/` 对 `IntelItem.truth` 零引用
- [ ] 每辆车的 `location`、每个线人的 `hangout` 都能解析到地图城区
- [ ] 行动进行中，facade 拒绝一切其他动作
- [ ] 任何玩家动作之后刷新页面都不丢进度
